# Reading the measurements

The [Tier 3 comparison](../checkpoints/tier3/results/README.md) adds twelve databases on a matched 500-product test workload. Client RSS and logical export size are measured in each raw run. Separate server usage is recorded in the [runtime evidence](../research/phase5-local-runtime.json) as post-run samples.

[leaderboard.md](leaderboard.md) and `plots/` are generated by `scripts/run_bench.py` from immutable JSON files under `runs/`. A run records every measured request, repeated QPS, configuration, source hashes, lock hash, installed versions, dataset/query hashes, model identity, and hardware. This checkout has no Git commit; its source-file hash supplies provenance instead.

## What each metric means

- **Recall@k** compares returned neighbors with independent blocked exact search over the same stored vectors and the same eligible filter set. Reference scoring accumulates in float64, while TinyVec operates in float32. At the kth boundary, scores within `max(1e-7, abs(cutoff) * 1e-6)` are numerical ties. Strictly closer neighbors must still be retrieved; tied neighbors fill only the remaining slots. Strict ID recall is also retained to expose ordering differences.
- **Precision@k, MRR, nDCG@k** compare IDs with synthetic relevance grades. Precision divides by requested k; MRR rewards the first relevant item; nDCG rewards relevant items near the top. Relevance is a different question from reproducing exact neighbors.
- **p50/p95/p99 latency** summarize individual retrieval calls, excluding embedding, data loading, insertion, quality calculation, and rendering. Each published configuration warms up 20 requests, then measures 100 queries over five seeded, shuffled repetitions. p99 remains noisy for small samples.
- **QPS** is completed serial requests divided by measured wall time, averaged across repetitions. Standard deviation shows repeat variation. It includes loop bookkeeping and is not concurrent service throughput.
- **Insertion/build** are separate wall times. TinyVec's build prepares its matrix; SQLite-vec's scalar scan has no ANN index build.
- **Memory** is process RSS sampled every 10 ms, including the client and its loaded libraries. A brief peak can be missed. Baseline, peak, and delta are reported. No server memory is claimed.
- **Persisted bytes** count the saved snapshot, not package installation, raw source data, or a server's operational disk footprint.

An empty eligible set has null neighbor recall and is excluded from its mean. Fewer-than-k sets use their actual eligible neighbor count for recall. Duplicate result IDs cannot earn repeated credit. A successful report has zero errors; failures abort the run instead of publishing partial timings as a complete result. Load-test failure rates arrive in the operations phase.

## Compare like with like

The [Tier 2 checkpoint](../checkpoints/tier2/results/README.md) selects settings on development queries and reports held-out results. Its disk workload and feature observations have their own raw files and timing boundaries. The indexed store saves full vectors and the build recipe. An index's logical payload or native serialized size is reported separately from both process RSS and snapshot size.

Groups require matching dataset/query hashes, hardware, metric, k, thread count, embedding space, and recall semantics. Filter/query mixes are in raw files and type-level metrics. Do not compare hashing fixture scores with MiniLM catalog scores or promote a local scalar-scan result into a vendor-wide claim. All foundation configurations use one thread for controlled numerical libraries and concurrency one.

The fixture tests plumbing with deterministic token hashing; it is not a semantic model. The catalog uses the included float16-rounded MiniLM vectors. The first diagnostic run used strict ID recall and remains in its own group. A later diagnostic catalog run used an earlier relevance-grade rule; its different query hash keeps it separate. Current judgments no longer penalize an unrequested color in ordinary text queries.

Initial configs deliberately use all query splits for descriptive coverage. They are not a held-out model-selection result. Use `split: development` while tuning, then an untouched `split: test` configuration for a final claim. Photo queries are excluded because frozen text surrogates cannot measure image retrieval.

The [foundation report](../docs/PHASE_2_REPORT.md) identifies the initial measurements. The [Tier 1 report](../docs/PHASE_3_REPORT.md) includes the matched 1k TinyVec and FAISS comparison. Module result pages also contain teaching experiments such as cache hit/miss timings; those measure different operations from the retrieval-only rows here. New measurements append raw files; the report generator rebuilds tables and plots without modifying old evidence.
