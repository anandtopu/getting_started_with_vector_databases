# Feature map: coverage contract

**Phase 8 delivery status.** All 24 core and four bonus modules have execution evidence. The four final bonus feature configs and result anchors are linked below. [Final audit](DEFINITION_OF_DONE.md) separates local verification from hosted CI and publication.

For each feature ID `F`, reserve `configs/bench/F.yaml` and `results/leaderboard.md#F`. No rows or measured numbers are inserted into the actual leaderboard until the harness runs. These identities apply to every row, including operations experiments; recovery/quality measurements remain separate from ANN comparisons. Module numbers resolve to paths in [the target tree](REPOSITORY_TREE.md) and [learning path](../LEARNING_PATH.md). A row's real example lives at `modules/<module>/examples/02_production.py` unless a specific additional filename is named. Multiple rows may share an example only when it stays clear and roughly 120 lines; otherwise split it into numbered examples.

Future local paths are code spans intentionally. On implementation, replace them with real links, add explicit run IDs/hardware, and enforce link existence in `scripts/check_course.py`. Each feature must also appear in its module's explanation/analogy, diagram, use case, exercise/solution, and use/not-use guidance. The standard module template is mandatory.

## Completion rules

The optional [local Weaviate generation profile](../configs/bench/weaviate_generation.yaml) also has [native execution evidence](../results/leaderboard.md#weaviate_generation). It retrieves a title before calling the pinned local model.

Each row needs a successful script run, reference-solution acceptance tests, an actual config, a measured raw result and leaderboard anchor, and valid local/source links before it can be marked complete. Optional features carry explicit capability and environment requirements; if a proposed native API cannot be confirmed, record the substitution and its semantic differences in the verification notes. No claim of native hybrid, quantization, durability, or isolation is inferred merely from the existence of a client package.

Feature-map execution coverage and teaching coverage are separate checks: a running wrapper around another module does not count as three distinct examples. The learning path tracks every requested module topic; the final audit will reconcile this map, module objectives, code ownership, and actual results in both directions.
